# AIYOUDSH v0.8.7 · 官方新版兼容

旧增强包固定了官方应用的版本、构建提交和模块校验值。官方更新后继续运行旧安装器，会在写入配置前停止，并提示版本不一致。本次为三种平台分别更新适配，保留精确校验。

| 平台 | 本次适配的官方版本 | 官方构建 |
| --- | --- | --- |
| Windows x64 | 0.2.2-rc.5 | 3f85d888b1297107937d9bd5b853f7e733e179a4 |
| macOS Apple Silicon arm64 | 0.2.2-rc.5 | 3f85d888b1297107937d9bd5b853f7e733e179a4 |
| macOS Intel x64 | 官方现有 mac-x64 feed 的 0.2.1-rc.4 | df71bd356c39b338b4269c1ab97fdb7f78e7243e |

## 适配内容

- 新版原生目录选择的 factory 插槽与菜单锚点，保留旧接口调用。
- 对接新版原生工作区／会话菜单和新建会话的导入入口；导出、复制与权限仍由官方控制器处理，旧版菜单继续兼容。
- 聊天、输入区、顶栏、右侧面板的官方 CSS 映射；新版用户气泡使用原生 `data-message-bubble` 标记，保留原主题的边距、圆角和透明度。
- 按实际目标更新界面版本标识；保留原始恢复源码的来源标识。
- Windows 版本不匹配提示补充当前版本和安装包支持版本，只显示经过格式校验的版本字符串。
- 新版精确基线独立保存，旧官方版本可通过 `--upstream-version` 显式构建。三个平台不互换运行库或媒体组件。

## 获取与验证

构建产物在 [Verify 工作流](https://github.com/yubowen123/AIYOUDSH/actions/workflows/verify.yml)中按平台分别提供；正式 Release 发布与 CI 构建是两件事。

所有安装包均从各自原生 runner 构建。检查包括官方包的哈希、Mac 签名/架构、隔离用户目录中的安装、重复安装、状态与卸载，以及官方运行时加载。Windows 另有真实 PE 安装器编译与自测截图。具体成功或失败以对应提交的工作流结果为准。

隔离检查不发送模型请求，也不代表 Windows / Intel 完整桌面聊天、所有第三方插件及用户真实项目已验收。本机已打开的旧版官方应用不会为了构建而被覆盖或重启。
