# v0.8.4 Intel Mac 支持

AIYOUDSH 新增独立 macOS Intel（x64）增强包，包含真实 x86_64 AppKit 安装器及 FFmpeg/FFprobe；Apple Silicon 的运行组件与安装器保持独立。增强包不包含或改写官方应用。

## 兼容基线

| 目标 | 官方版本 / 构建 | 额外条件 |
| --- | --- | --- |
| Intel x64 | `0.2.1-rc.1 / ed75efeffee65f9fe93625bbd76a68cb219aaaf9` | macOS 13+，官方 Intel ZIP |
| Apple Silicon arm64 | `0.2.1-rc.2 / 332895e0f7c9d4dbfb29729f5eb367fa263ff986` | 官方 ARM 应用；既有 FFmpeg 8.1 声明 macOS 26+ |
| Windows x64 | `0.2.1-rc.2 / 332895e0f7c9d4dbfb29729f5eb367fa263ff986` | 构建验证保留；正式下载仍指向历史 v0.5.0，画布新业务未完整桌面验收 |

Intel 当前官方更新源发布的是 rc.1，未用猜测的 rc.2 URL。官方 ZIP 的大小、SHA256/SHA512、签名及组件已取证；25 个关键包、155 个文件静态比对，宿主行为一致，差异为版本元数据、CSS生成路径/类名与侧栏版本标识。Intel CSS映射335项，其中主题引用31项，冻结恢复分区未改写。安装仍逐一校验精确归档及组件，不能绕过检查安装其他版本。

## 包内变化

- 构建器支持 `darwin-x64`，保留 ARM/Windows；每个运行包只保留对应媒体架构。
- Intel 媒体使用未改动的 6.1.1-tessus x64 原件，与 ARM 8.1 分开；GPL许可、源码、构建参数、发布元数据差异和文件哈希随包。
- Swift 支持显式 x64/arm64，编译后核对 Mach-O 与 lipo；打包拒绝目标/manifest不一致，stage按平台分离。
- 新增原生 Intel CI 与隔离官方应用检查，记录真实 x64 进程、硬件/Rosetta证据、认证HTTP、SQLite、sharp、插件装配和卸载恢复；不触达正式app/profile，不调用模型。
- 修复本地 Codex CLI 在等待宿主工具时取消后，关闭适配器可能早于子进程退出的问题；关闭操作会等待全部已启动的退出流程，并覆盖重复关闭的确定性回归。

## 使用

[下载 v0.8.4](https://github.com/yubowen123/AIYOUDSH/releases/tag/v0.8.4)，Intel 选 `macos-x64.zip`，M 系列选 `macos-arm64.zip`。先打开相应官方应用完成初始化，再完整解压增强包并运行安装器。升级、安装目录与冲突保护见[安装说明](../installation.md)，开发及交叉打包见[源码指南](../development.md)。

构建、静态比对、Rosetta与原生CI分别证明各自范围；完整 Intel 用户桌面的手工操作、全部主题×业务组合以及真实供应商模型生成仍应独立验收。最终构建结果和附件SHA见GitHub发行页，不将准备状态写成验收成功。
